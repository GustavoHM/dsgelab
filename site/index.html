dsgelab

A model is declared once, as lists of state, jump and shock names and a residual function. The steady state, the first-order solution, impulse responses, moments, second-order risk corrections, perfect-foresight transitions and calibration on targets are all computed from that declaration.

Why it exists

The package is built so that the stochastic block and the deterministic transition are the same model.

In applied work, a perturbation solution is often built on one set of equations while the transition path is solved by a hand-written fixed point on another set, similar to the first, written by the same person, and not identical. Here both call the same residual function, so the equations behind them cannot differ.

Two checks run on every solve, and three more take one call each. If the determinacy condition fails, solve raises BlanchardKahnError instead of returning a solution. Convergence of the steady state is decided by the size of the residual, and the solver's success flag plays no part in that decision. The user runs the other three. check_identity evaluates an identity the model does not impose, such as Walras' law, without adding it to the model's equations. .accuracy() measures the order of accuracy of the approximation from how fast the residual falls as the displacement is halved. Whether a calibration is identified is reported by target_jacobian, since calibrate does not check it.

Install

pip install dsgelab
pip install "dsgelab[symbolic]"

The package depends only on numpy and scipy. sympy is optional and serves the text front end, which supplies exact analytic derivatives.

dsgelab --example rbc        # solves a bundled model and prints the diagnostics

2. Declare your own model

A model consists of three lists of names and a function. The function reads variables by name, from cur for period t and from nxt for t+1.

import numpy as np
from dataclasses import dataclass
from dsgelab import Model, solve

@dataclass
class P:
    alpha: float = 0.36
    beta:  float = 0.99
    delta: float = 1.0
    gamma: float = 1.0
    rho:   float = 0.95

def equations(nxt, cur, eps, p):
    y  = cur.a * cur.k ** p.alpha
    y1 = nxt.a * nxt.k ** p.alpha
    return [
        nxt.k - ((1 - p.delta) * cur.k + y - cur.c),                    # resource
        cur.c ** -p.gamma - p.beta * nxt.c ** -p.gamma                  # Euler
            * (p.alpha * y1 / nxt.k + 1 - p.delta),
        np.log(nxt.a) - p.rho * np.log(cur.a) - eps.eps_a,              # technology
    ]

mine = Model(states=["k", "a"], jumps=["c"], shocks=["eps_a"], equations=equations)
sol_mine = solve(mine, P(), guess={"k": 0.2, "a": 1.0, "c": 0.36})

sol_mine.P                    # transition of the states
sol_mine.accuracy()           # the implied order must come out ~2
sol_mine.P

When variables are read from a vector by position, swapping one index for another raises no error, and the program silently solves a different model from the one intended. Reading each variable by name rules that mistake out.

The residual, the Jacobian and the Hessian are differentiated exactly. Exact derivatives matter at second order because a second difference divides by the square of the step, so a numerical Hessian carries about half the significant digits of the residual it came from.

The transition is solved by a stacked-time Newton method on the same residual function that the perturbation linearises. A surprise is a change in terminal with constant parameters, and a statutory schedule known in advance is passed as a sequence of parameter values, one per period.

6. Calibrate parameters on targets, and know whether they are identified

def observables(ss, p):
    y = ss["a"] * ss["k"] ** p.alpha
    return {"ky": ss["k"] / y, "iy": p.delta * ss["k"] / y}   # capital-output, investment share

res = dsg.calibrate(
    mine, P(),
    free={"beta": 0.95, "delta": 0.5},
    targets={"ky": 10.0, "iy": 0.25},
    guess={"k": 0.2, "a": 1.0, "c": 0.36},
    observables=observables,
    bounds={"beta": (0.5, 0.999), "delta": (0.001, 1.0)},
)
print(res.report())

ident = dsg.target_jacobian(mine, replace(P(), **res.values), free=["beta", "delta"],
                            targets=["ky", "iy"], guess={"k": 0.2, "a": 1.0, "c": 0.36},
                            observables=observables)
ident["identified"]        # True: two targets pin the two parameters

The capital-output ratio and the investment share set β and δ together. In closed form δ = iy/ky = 0.025 and β = 1/(α/ky + 1 − δ) = 0.98912, which is what calibrate returns. Evaluated at that solution, target_jacobian reports that the two targets identify the two parameters. With β and α free and the capital stock as the only target, the elasticity matrix has rank one, and null_directions gives the combination of the two parameters that leaves the target unchanged. Done by hand, a calibration becomes nested bisections, one per parameter, each treating its target as if one parameter set it, although the targets are jointly determined. When that matrix lacks full rank, the calibration is not identified, and tightening the solver tolerance does not change that.

8. Derive the first-order conditions (FOCs) instead of writing them

You declare only the problem, and the package differentiates the Lagrangian. Because the derivatives are taken symbolically, the sign errors and omitted terms of differentiation by hand cannot enter the conditions. Those errors do not show up in the steady state, so a steady state that solves does not rule them out.

from dsgelab.blocks import Problem, optimality_conditions

prob = Problem(
    "log(c)",                                   # period return
    controls=["c", "i"], states=["k"], exogenous=["a"],
    constraints=["c + i = a*k**alpha",          # resources
                 "k(+1) = (1-delta)*k + i"],    # accumulation
    discount="beta", parameters=["alpha", "beta", "delta", "rho"],
)
foc = optimality_conditions(prob)

for eq in foc["equations"]:
    print(f"{eq:60s}  # {foc['detail'][eq]}")   # each equation says where it came from

derived = dsg.from_equations(
    foc["equations"] + ["log(a(+1)) = rho*log(a) + eps_a"],
    states=["k", "a"], jumps=foc["jumps"], shocks=["eps_a"],
    parameters=["alpha", "beta", "delta", "rho"])
lm_1 + 1/c                                                    # FOC for control c
lm_1 - lm_2                                                   # FOC for control i
lm_2 - beta*lm_2(+1) + beta*delta*lm_2(+1) - a(+1)*alpha*beta*lm_1(+1)*k(+1)**alpha/k(+1)  # Euler equation for state k
c + i - a*k**alpha                                            # constraint 1: c + i = a*k**alpha
k(+1) - i - k*(1 - delta)                                     # constraint 2: k(+1) = (1-delta)*k + i

Transversality conditions, inequality constraints and problems whose Euler equation does not follow from the derivative of next period's Lagrangian with respect to the inherited state are left to the modeller. The package derives the conditions of the problem that was declared, so an error in the declaration passes into the equations. Choosing the problem remains the modeller's task.

Third order covers the full decision rule and the stochastic steady state. The cubic terms (g_kkk, h_kkk) are verified by the order of accuracy, since halving the displacement divides the residual by sixteen. Risk enters through g_ssk, h_ssk and the state and innovation blocks ghxss and ghuss. On the log AR(1), h_ssk[a, a] = ρσ². Simulation uses the pruned rule with every cubic innovation block. stochastic_steady_state(to) computes the fixed point of the full unpruned rule. With sparse=True, direct_limit=0, the solver stores independent symmetric state triples and avoids the large dense tensors; explicit decision-rule composition still forms dense arrays.

In dsgelab the state at t is the one available at t. In Dynare the predetermined variable is the one decided at t. A conversion by hand has to translate one timing into the other. The exporter does this translation, and it also writes exogenous processes one period back, so that the innovation appears without a lag. In the round trip the package writes the .mod and Dynare solves it. On the three reference models the two solutions differ by less than 1e-13 in steady state, IRFs and moments.

11. Optimal policy: the Ramsey planner

nk = dsg.ramsey_model(
    ["x - x(+1) + (1/sigma)*(i - pi(+1)) = 0",      # IS
     "pi = beta*pi(+1) + kappa*x + u",              # Phillips
     "u(+1) = rho*u + e"],                          # cost shock: exogenous process
    states=["u"], jumps=["x", "pi", "i"], shocks=["e"],
    parameters=["beta", "sigma", "kappa", "lam", "rho"],
    instruments=["i"],                              # the variable with no equation of its own
    objective="-(pi**2 + lam*x**2)/2", discount="beta")
pn = dict(beta=0.99, sigma=1.0, kappa=0.1, lam=0.25, rho=0.5)
ss_nk = dsg.ramsey_steady_state(nk, dict(u=0, x=0, pi=0, i=0), pn)
r = dsg.solve(nk, pn, steady=ss_nk).irf("e", size=1.0, percent=False)

x_lag = np.r_[0.0, r["x"][:-1]]
abs(r["pi"] + pn["lam"] / pn["kappa"] * (r["x"] - x_lag)).max() < 1e-12   # targeting rule
abs(r["pi"] + pn["lam"] / pn["kappa"] * (r["x"] - x_lag)).max() < 1e-12
True

The planner's conditions are derived symbolically from the private-sector equations, and the result is an ordinary Model, with the multipliers and their lags as variables. The perspective is the timeless one, as in Dynare's ramsey_model. In this New Keynesian example the response follows Galí's targeting rule, π_t = −(λ/κ)(x_t − x_{t−1}), with an error below 1e-12.

A news item is a new expected path of shocks and parameters, and a new terminal steady state. At each news item the agents replan from the states already realised. The procedure is that of Dynare's perfect_foresight_with_expectation_errors_solver, and a .mod with the information table in CSV becomes the list of news items through ModFile.news.

EstimationProblem holds the model, the data, the priors and the observables. The priors are Dynare's, set by mean and standard deviation. Observables may be in levels or in logs, may carry measurement error and may have missing values. From the problem the package computes the mode with the Laplace approximation, maximum likelihood, Metropolis with R-hat and effective sample size, SMC, the prior predictive check and the marginal likelihood. ModFile.estimation_problem builds an EstimationProblem from a .mod with estimated_params and varobs.

Each period the shock arrives, the states it leads to are computed, and the agents solve a nonlinear problem that reaches the steady state horizon periods later. With order > 0 the shocks of the following periods are integrated by Gauss–Hermite quadrature over a tree of plans, sparse or full, with the optional second-order risk correction (hybrid). The algorithm and these options are those of Dynare's extended_path.

identification checks, at one point, whether the distribution of the observed series pins down the free parameters, with the three criteria of Dynare's identification command: the derivatives of the moments (Iskrev), of the spectrum (Qu and Tkachenko) and of a minimal state space (Komunjer and Ng). With order=2 the likelihood comes from the pruned second-order rule, and nonlinear_filter chooses between the inversion filter and the bootstrap particle filter, which is the default. The AR(1) of example 14 is linear, so its second-order rule equals the first-order one and both filters must reproduce the Kalman likelihood. hmc and nuts follow the gradient of the log posterior, computed by log_posterior_gradient as in example 21, and use the covariance at the mode as the inverse mass matrix. During burn-in, a heuristic picks a first step size and dual averaging (Hoffman and Gelman, 2014) moves it toward an acceptance rate of 0.8. nuts doubles each trajectory until it turns back on itself and draws a point from it with multinomial weights, so it has no number of leapfrog steps to set. hmc takes leapfrog steps and varies the step size by up to 20% from one draw to the next. In two runs on this problem, the effective sample size of rho from NUTS was between 70% and 100% of the number of draws, and about 6% of it for random-walk Metropolis. Both posterior means lie within a third of a Laplace standard deviation of the mode. NUTSResult also reports divergences, trajectories that reach max_depth and the mean tree depth. The test suite checks both samplers against the exact posterior of an AR(1) coefficient, computed by quadrature, and against a long Metropolis–Hastings run. They run at first order only, because they need the gradient of the Kalman likelihood. Its recursion costs about five times one evaluation of the likelihood, and for that reason the example uses 100 observations.

What is in the box

Steady state

Positivity solved in logs, and anchors through an outer loop for terms that depend on the steady state itself.

First order

Ordered real Klein/QZ, with Blanchard–Kahn enforced and the determinacy margin reported.

Second order

Generalised Sylvester equation, risk corrections, pruned simulation and the ergodic mean in closed form.

Third order

Full decision rule in Dynare's form, with the cubic block verified at order 4 and every innovation and risk block (ghxss, ghuss). Example 9 solves with sparse tensors and describes the stochastic steady state.

From FOCs to .mod

Declare the Lagrangian, derive the conditions, solve, and export to Dynare or MacroModelling.jl.

Perfect foresight

Stacked-time Newton with a sparse Jacobian and announced parameter paths.

Calibration

Targets solved jointly, with an identification diagnostic based on rank and null directions.

Identification

Dynare's three local criteria (moments, spectrum, minimal system) and its collinearity search, with the same verdicts.

Occasionally binding constraints

OccBin with any number of constraints, time-varying rules and surprise shocks, as in Dynare's +occbin.

Extended path

Deterministic and stochastic, on a sparse or full tree, with the hybrid risk correction.

Models in levels

Declared trends, the balanced-growth check and the balanced growth path.

Checks

Order of accuracy, independent identities, slack of smoothed constraints, comparison between solutions.

The one convention you have to get right

eps is the innovation dated t+1, unknown at t, with E_t eps = 0. An AR(1) is written as

nxt.a - p.rho * cur.a - eps.eps_a

Writing it the other way round raises no error. If the innovation is treated as known at t, the model becomes deterministic within the period, so the first-order solution does not change and every second-order risk correction comes out zero without a warning. The library cannot detect this mistake in a model you declare. The package's own test suite checks the convention on log a' = rho log a + eps, where the second-order coefficient h_ss must come out at sigma², so that the correction in the rule is sigma²/2, the Jensen term.

Validation

The validation has three layers. The test suite compares the package with closed forms and answers known analytically. The scripts in validation/ compare it with Dynare on Dynare's own examples and test files, with MacroModelling.jl on one calibration equation, and with the original MATLAB code of Heutel (2012), shown in Replications. A last comparison, on an applied model from an unpublished paper by the author, cannot be rerun from the repository.

In the second layer both the models and the reference software come from other authors. The third uses the same reference software on a model of the author's own. Each feature is validated against an independent reference where one exists (another implementation, a closed form or a published result). A few rest on internal tests only, namely autocorrelations, variance decomposition, pruning, the second-order generalised IRF, announced parameter paths and the Blanchard–Kahn check, and the export to MacroModelling.jl has no round trip.

Against closed forms

Of the package's 148 tests, those in this layer compare its output with answers that can be derived on paper. With log utility and full depreciation, the RBC solution must equal P = [[α, 1], [0, ρ]]. In the three-equation New Keynesian model with φx = 0.125, the Taylor rule must give a determinate equilibrium at φπ = 1.5 and an indeterminate one at φπ = 0.8. On a lognormal AR(1), the second-order coefficient h_ss has to equal sigma², so the decision rule shifts by sigma²/2, the Jensen term. The perfect-foresight transition is compared with the closed-form path k' = αβk^α. The order-of-accuracy test requires that halving the displacement divide the first-order residual by four and the second-order residual by eight.

Survey of 9 September 2026, revised on 11 and 12 October 2026, with gEconpy 2.2. Later releases of these packages may change some cells, and docs/comparison.md gives the source of each one.

If you need only first order with Bayesian estimation, install gEconpy. It derives the first-order conditions from declared blocks, accepts a declared analytic steady state, estimates by Bayesian methods (through PyMC) and exports to Dynare, as dsgelab does, but it has no second-order solution. For global methods beyond Chebyshev collocation, such as time iteration and value iteration, dolo documents more. Heterogeneous agents are outside dsgelab, and sequence-jacobian and econpizza solve those models.

In dsgelab a declared problem goes from the derived first-order conditions to a solution and to an export for Dynare or MacroModelling.jl, with the timing translated automatically. The same residual function serves the perturbation and the deterministic transition. The second-order solution runs within Python, without calling Dynare through Octave. Blanchard–Kahn and the convergence of the steady state are checked on every solve, the order of accuracy and the identification of a calibration take one call each, and the only dependencies are numpy and scipy. In the three uses named in the note above (Bayesian estimation through PyMC, global methods and heterogeneous agents), the packages named there offer more than dsgelab. The full table, which separates the cells verified by installing a package from those read only in its documentation, is in docs/comparison.md.

Citing

If the package contributed to a published result, it belongs in the references, as any other methodological input does. The reference should include the version, because a number that reproduces only under one version cannot be reproduced without knowing which.

In the text

Next to the result, give the version along with the name of the package, as in the sentence below.

The model was solved with dsgelab 0.5.0 (Moreira, 2026), by second-order perturbation.

Cite an archived version when one exists. The content behind a repository URL changes and the link can stop working, so the URL alone does not identify the version that was used. Each release of dsgelab is archived on Zenodo, and the DOI that Zenodo assigns to it is the reference to cite: version 0.5.0 is 10.5281/zenodo.23456475, and the concept DOI 10.5281/zenodo.23456474 resolves to the latest release. The CITATION.cff file at the package root, which carries the author's ORCID and the concept DOI, is in the format GitHub reads, and the "Cite this repository" button serves the entry from it.

Citing the tools this package uses

Cite Dynare when the model was exported to it or checked there, and MacroModelling.jl in the same case. NumPy and SciPy ask explicitly to be cited, and every computation in dsgelab runs on them.
